# Live Chat Palette — v1.0 Design

**Target:** Google Chrome  
**Extension Platform:** Manifest V3  
**Version:** v1.0  
**Created:** 2026-08-23

## 1. Overview

Live Chat Palette is a Chrome extension that improves YouTube Live chat participation by adding a compact palette near the native chat input.

The extension provides quick access to:

- Frequently used message presets
- Channel-specific message presets
- YouTube channel custom emojis available to the current user
- Favorite custom emojis

The extension does **not** post through the YouTube Data API. Instead, it acts as a UI-assistance layer on top of YouTube's existing Live Chat input, emoji picker, and send flow.

The core v1.0 goal is:

> Add channel-aware favorite custom emojis and message presets to YouTube Live Chat so users can participate quickly without introducing unsafe automation or accidental posting.

---

## 2. Product Goals

YouTube Live viewers often repeat the same messages and channel-specific member emojis during a stream. Today this usually requires repeatedly opening the native emoji picker, locating the desired emoji, typing common messages, and then submitting them.

Live Chat Palette shortens that flow to a small number of explicit user actions.

Primary use cases include:

- VTuber streams
- Game streams
- Music/live-event streams
- Member-only streams
- Any Live Chat where users frequently reuse the same messages or custom emojis

---

## 3. Product Principles

### 3.1 Assist posting; do not automate participation

The extension is a posting aid, not an auto-chat tool.

v1.0 must not implement:

- Periodic automatic posting
- Automatic posting when a stream starts
- Conditional or event-triggered posting
- Bulk posting
- Multi-stream simultaneous posting
- Automatic retry after an ambiguous send result

Every actual post must ultimately originate from an explicit user action.

### 3.2 Use YouTube's native chat behavior

The extension must rely on YouTube's own chat input and posting behavior whenever possible.

YouTube remains responsible for:

- Authentication state
- Membership eligibility
- Whether a custom emoji is currently usable
- Chat availability
- Slow mode
- Subscriber/member-only chat restrictions
- Rate limits and other posting restrictions

The extension must not attempt to reproduce or bypass these checks.

### 3.3 Fail closed

When the extension cannot confidently identify the required YouTube UI, it must stop the operation rather than guess.

Example:

```text
Chat input not found
  -> do not insert or send
  -> show an unsupported/currently unavailable state
```

Incorrect DOM interaction is considered worse than temporary feature unavailability.

### 3.4 Isolate YouTube-specific behavior

YouTube DOM selectors and interaction logic must be contained in dedicated adapter classes.

```text
UI
  -> Application Services
      -> YouTube Adapters
          -> YouTube DOM
```

Feature/UI components must not scatter direct YouTube selectors throughout the codebase.

The extension mounts a compact panel near the native YouTube Live Chat input.

Example:

```text
+--------------------------------+
| ★ Emojis    💬 Presets      ⚙  |
+--------------------------------+
| [emoji] [emoji] [emoji]        |
|                                |
| [Cute!]                        |
| [That was amazing!]            |
| [Thanks for the stream!]       |
+--------------------------------+

+--------------------------------+
| YouTube chat input...          |
+--------------------------------+
```

The extension should visually integrate with YouTube without replacing or heavily rearranging the native chat UI.

### 6.1 Tabs

Two primary tabs are provided:

- Favorite Emojis
- Message Presets

The last selected tab is persisted.

### 6.2 Collapse behavior

The palette can be collapsed.

```text
[ Live Chat Palette ▲ ]

-> collapsed

[ Live Chat Palette ▼ ]
```

Persist:

```ts
collapsed: boolean;
```

## 7. Message Presets

### 7.1 Data model

```ts
interface MessagePreset {
  id: string;
  text: string;
  scope: "global" | "channel";
  channelId?: string;
  order: number;
  createdAt: number;
  updatedAt: number;
}
```

### 7.2 Global presets

Global presets are visible on every supported Live Chat.

Examples:

```text
LOL
Cute!
Amazing!
Thanks for the stream!
```

### 7.3 Channel presets

Channel presets are visible only for the matching YouTube channel.

The stable YouTube `channelId` must be used as the logical key. Display names must not be used as identifiers.

---

## 8. Preset Click Behavior

### 8.1 Default click

Normal click inserts the preset into the YouTube input field but does not send it.

```text
Preset click
  -> insert into native chat input
  -> user reviews message
  -> user sends normally
```

This is the default behavior.

### 8.2 Explicit instant send

Instant-send is available but disabled by default.

Setting:

```text
Send immediately when preset is clicked
[ OFF ]  <- default
[ ON  ]
```

When enabled:

```text
Preset click
  -> insert
  -> validate send availability
  -> trigger native send
```

### 8.3 Modifier send

Even when instant-send is disabled:

- `Ctrl + Click` on Windows/Linux
- `Command + Click` on macOS

performs an explicit immediate send.

Therefore the safe default interaction is:

```text
Click              -> insert only
Cmd/Ctrl + Click   -> insert and send
```

## 9. Chat Input Adapter

Direct assignment such as the following is prohibited:

```ts
element.innerHTML = text;
```

YouTube's own editable input state must be respected.

Provide a dedicated adapter:

```ts
interface ChatInputAdapter {
  findInput(): HTMLElement | null;
  readDraft(): string;
  insertText(text: string): Result<void>;
  send(): Result<void>;
  isSendEnabled(): boolean;
}
```

Expected insertion flow:

```text
focus
  -> determine current selection/caret
  -> insert text
  -> dispatch the appropriate input event
  -> verify YouTube's input state changed
```

If insertion success cannot be confirmed, an immediate send must not occur.

### 9.1 Preserve existing draft text

Existing user text must never be silently replaced.

Presets are inserted at the current caret position whenever possible.

Example:

```text
Before:
Suisei is

Preset:
amazing!

After:
Suisei is amazing!
```

---

## 10. Custom Emoji Support

In this document, "custom emoji" refers to YouTube's channel-provided custom/member emojis.

The extension must not fabricate an emoji representation and inject an arbitrary image into the chat editor.

The preferred flow is:

```text
Live Chat Palette favorite
  -> EmojiAdapter
      -> native YouTube emoji capability
          -> native chat input
```

This ensures YouTube remains the authority over whether the emoji is actually available to the current account.

---

## 11. Emoji Adapter

```ts
interface EmojiAdapter {
  openPicker(): Promise<Result<void>>;
  closePicker(): Promise<void>;
  scanAvailableEmojis(): Promise<Result<AvailableEmoji[]>>;
  insertEmoji(emoji: EmojiReference): Promise<Result<void>>;
}
```

### 11.1 Discovery

Custom emojis should be discovered from the native YouTube emoji UI available to the current user.

Do not use a membership API or infer eligibility independently.

Basic flow:

```text
Refresh emojis
  -> access native YouTube emoji picker
  -> inspect currently available emojis
  -> identify custom/channel emojis
  -> update local palette metadata
```

### 11.2 Emoji reference model

```ts
interface EmojiReference {
  id: string;
  channelId: string;
  emojiKey: string;
  displayName: string;
  imageUrl?: string;
  lastSeenAt: number;
}
```

`imageUrl` must not be treated as a stable logical identifier because the URL may change.

`emojiKey` is the preferred logical reference where the current YouTube UI exposes a stable-enough key.

### 11.3 Unavailable emoji

If a previously favorited emoji is not currently available, disable it instead of attempting to send it.

```text
[emoji 🔒]
Currently unavailable
```

Possible causes do not need to be distinguished in v1.0. They may include:

- Membership status changed
- Emoji removed or renamed
- Different channel context
- YouTube UI changed

### 11.4 Emoji refresh

Provide an explicit action:

```text
↻ Refresh emojis
```

Attempt refresh on:

- First palette load for a channel
- Channel context change
- Full page reload

However, automatic synchronization must not visibly open or disrupt the user's native emoji picker. If native UI interaction would be intrusive, require the explicit refresh action.

## 12. Channel and Video Context

```ts
interface VideoContext {
  videoId?: string;
  channelId?: string;
  channelName?: string;
}
```

Use a dedicated adapter:

```ts
interface WatchContextAdapter {
  detectVideoId(): string | null;
  detectChannelId(): string | null;
  detectChannelName(): string | null;
}
```

DOM-based detection details must remain inside this adapter.

If `channelId` cannot be resolved, global presets may remain available, but channel-specific features must fail closed.

---

## 13. YouTube SPA Navigation

YouTube commonly changes videos without a full page reload.

The extension must not assume a single initialization per document lifetime.

Observe relevant navigation/context changes:

```text
Navigation change
DOM change
Video context change
```

On context change:

```text
old context
  -> invalidate channel-specific state
  -> detect new context
  -> load matching presets
  -> re-evaluate emoji availability
```

Avoid reacting to every arbitrary DOM mutation as a full navigation event.

---

## 14. iframe Handling

Live Chat may run inside an iframe. Content scripts should be configured to support matching frames where necessary.

Example concept:

```json
{
  "content_scripts": [
    {
      "matches": ["https://www.youtube.com/*"],
      "all_frames": true
    }
  ]
}
```

Each injected script must determine whether it is running in:

- Main watch-page frame
- Live Chat frame
- Irrelevant YouTube frame

and initialize only the responsibility appropriate for that context.

## 15. Architecture

```text
YouTube Watch Page
       |
       | VideoContext
       v
Watch Content Script
       |
       v
Service Worker
       |
       | Context / messaging
       v
Live Chat Content Script
       |
       v
Live Chat Palette UI
       |
       +---- PresetService
       |
       +---- EmojiService
                  |
                  v
            YouTube Adapters
                  |
                  v
              YouTube DOM
```

### 15.1 WatchContentScript

Responsibilities:

- Detect supported YouTube page context
- Detect `videoId`
- Detect `channelId`
- Detect SPA navigation/context changes
- Publish context updates

### 15.2 ChatContentScript

Responsibilities:

- Determine whether current frame is Live Chat
- Mount the palette
- Detect destructive/reconstructive chat DOM changes
- Restore the extension UI if YouTube rebuilds its surrounding DOM

### 15.3 ServiceWorker

Responsibilities:

- Route messages between frames
- Share current video/channel context
- Coordinate session state
- Access extension storage when appropriate

The service worker must not access DOM APIs.

The design must not assume that a Manifest V3 service worker remains permanently alive.

### 15.4 LiveChatPalette UI

Responsibilities:

- Tabs
- Favorite emojis
- Presets
- Collapse/expand
- Error/unavailable states
- Link to settings/options

### 15.5 YouTube adapters

Responsibilities:

- Locate native chat input
- Insert text
- Detect/send via the native send control
- Discover native custom emojis
- Trigger native emoji insertion
- Resolve watch/channel context

## 16. Storage

Use:

```text
chrome.storage.local
chrome.storage.session
```

### 16.1 `chrome.storage.local`

Persistent user data:

- Message presets
- Favorite emoji references
- UI preferences
- Known channel metadata

### 16.2 `chrome.storage.session`

Temporary browser-session state:

- `tabId`
- `videoId`
- `channelId`
- `channelName`

Do not rely solely on service-worker global variables for recoverable state.

### 16.3 Schema

```ts
interface StorageSchema {
  schemaVersion: 1;

  settings: {
    instantSend: boolean;
    collapsed: boolean;
    lastSelectedTab: "emoji" | "preset";
  };

  presets: MessagePreset[];
  favoriteEmojis: EmojiReference[];

  channels: Record<
    string,
    {
      channelId: string;
      channelName?: string;
      lastSeenAt: number;
    }
  >;
}
```

### 16.4 Schema migration

Persist a schema version from the first release:

```ts
schemaVersion: 1;
```

All future storage changes must support explicit migrations such as:

```text
1 -> 2
2 -> 3
```

## 17. Extension Permissions

Keep permissions minimal.

Expected core permission:

```json
{
  "permissions": ["storage"]
}
```

Expected host scope:

```json
{
  "host_permissions": ["https://www.youtube.com/*"]
}
```

The final implementation should verify whether host permissions can be narrowed further without harming Live Chat support.

Do not request these unless a later implementation proves them necessary:

- `tabs`
- `history`
- `cookies`
- `identity`
- `webRequest`
- `downloads`
- `clipboardRead`
- `clipboardWrite`

## 18. Authentication and Network Policy

v1.0 uses no Google OAuth.

The extension must not require access to Google account credentials or tokens.

v1.0 also has no proprietary backend and no telemetry endpoint.

Expected data flow:

```text
Extension
  +-- YouTube DOM/native UI
  +-- Chrome extension storage
```

No user preset/comment data is sent to an extension-owned external server.

---

## 19. Privacy

Do not collect:

- Google account details
- YouTube account details
- Browsing history
- Comment history
- Membership history
- Posted message contents
- Usage analytics

User-created presets and extension preferences are stored locally.

---

## 20. UI Isolation

Use a Shadow DOM root for extension UI where practical.

```text
Extension mount
  -> ShadowRoot
      -> Live Chat Palette
```

Do not rely on YouTube CSS classes for the extension's own visual styling.

Support both light and dark environments using extension-owned theme variables and platform primitives such as `color-scheme` where appropriate.

---

## 21. DOM Rebuild Handling

YouTube may reconstruct the Live Chat DOM.

A scoped `MutationObserver` may be used to detect when the extension mount has disappeared.

```text
Relevant chat DOM changed
  -> check extension root
  -> missing?
      -> remount
```

Do not observe the entire YouTube document with expensive processing on every mutation.

Use a mount guard such as:

```html
<div data-live-chat-palette-root="true"></div>
```

Multiple simultaneous mounts are prohibited.

---

## 22. Selector Management

Selectors must be centralized in the YouTube integration layer.

Preferred layout:

```text
src/youtube/
  ChatInputAdapter.ts
  EmojiPickerAdapter.ts
  SendButtonAdapter.ts
  WatchContextAdapter.ts
  selectors.ts
```

Adapters may use multiple explicit strategies when necessary:

```text
Strategy A
  -> fail
Strategy B
  -> fail
Strategy C
  -> fail
Unsupported
```

Fallback logic must not select a vaguely similar element and click it merely because the preferred selector failed.

---

## 23. Error Handling

Use clear user-facing states.

### Chat unsupported

```text
YouTube's chat input could not be recognized.
```

### Emoji unsupported

```text
Custom emojis cannot currently be loaded.
```

### Channel unknown

```text
Channel information could not be detected.
Global presets are still available.
```

### Send failed

```text
The message could not be sent.
Please check the current chat state.
```

### 23.1 No automatic send retry

Never automatically retry a send operation.

An ambiguous result could otherwise cause duplicate messages.

---

## 24. Duplicate Send Protection

After an extension-triggered send, briefly lock extension send actions to guard against accidental double activation.

An initial implementation may use a short lock around approximately 800 ms, but this is purely UI protection and must not attempt to replace YouTube Slow Mode or rate limiting.

## 30. Extension Message Protocol

Frame/service-worker messages must use typed message definitions instead of duplicated string literals.

```ts
type ExtensionMessage =
  | {
      type: "CONTEXT_UPDATED";
      context: VideoContext;
    }
  | {
      type: "GET_CONTEXT";
    }
  | {
      type: "CONTEXT_RESPONSE";
      context: VideoContext | null;
    };
```

## 31. Popup Live Chat

Best-effort support is included in v1.0.

If a popup chat can be associated with a known `videoId`/channel context from the current browser session, channel-specific features may be enabled.

If the channel context cannot be resolved, provide only capabilities that can safely operate without it, such as:

- Global presets
- Explicit emoji refresh where native discovery remains possible

Do not add complex popup-specific scraping solely to make channel detection work in v1.0.

## 35. Logging

Development builds may use structured debug logging.

```ts
logger.debug();
logger.warn();
logger.error();
```

Production builds should avoid unnecessary debug output.

Never log:

- User draft contents
- Preset contents merely because they were clicked
- Posted messages
- Google/YouTube account identifiers beyond the minimum public channel context needed by the feature

---

## 36. Performance

Mutation observers and DOM scans must be narrowly scoped.

Do not perform a full YouTube DOM scan for every mutation.

Where appropriate, debounce repeated structural checks in the approximate range of 100–300 ms.

The extension should remain effectively idle when:

- The page is not a supported YouTube context
- Live Chat is absent
- The user is not interacting with the palette

---

## 37. Security

Prohibited:

- `eval`
- `new Function`
- Remote JavaScript execution
- External CDN scripts
- Downloaded runtime code
- Reading YouTube cookies
- Extracting Google authentication tokens

All executable extension code must ship inside the extension package.

## 39. v1.0 Acceptance Criteria

### Installation

- Installs successfully as a Manifest V3 extension
- Requests no unnecessary permissions

### YouTube integration

- Detects supported Live Chat contexts
- Does not interfere with normal YouTube viewing
- Does nothing intrusive when Live Chat is absent

### Presets

- Can be created
- Can be edited
- Can be deleted
- Can be reordered
- Supports global scope
- Supports channel scope

### Input safety

- Existing draft text is not silently destroyed
- Normal click does not accidentally post by default
- Explicit instant-send behavior works only when intentionally invoked

### Custom emojis

- Available custom emojis can be discovered through the native YouTube UI integration
- Favorite state can be saved
- Favorites can be inserted into the native chat input
- Unavailable favorites are not blindly sent

### Navigation

- Moving to another Live stream without a full reload refreshes channel-specific state
- Channel presets do not leak into unrelated channels

### Failure behavior

- Unknown/changed DOM results in a safe unavailable state
- No automatic send retry
- No duplicate send caused by extension retry logic

### Privacy

- No extension-owned external server is required
- No Google OAuth is required
- No analytics/telemetry is collected in v1.0

## 40. Quality Priorities

When trade-offs are necessary, use this order:

```text
1. Avoid accidental/incorrect posts
2. Do not break YouTube
3. Be useful in everyday Live Chat participation
4. Make YouTube DOM changes easy to repair
5. Keep interaction fast
6. Provide a polished UI
7. Add more features
```

A convenient extension that occasionally misposts is considered unacceptable.

- AI-assisted candidate text generation

Automatic unattended posting remains outside the intended product direction.

---

## 42. Final v1.0 Definition

Live Chat Palette v1.0 is complete when it can be described as:

> A Chrome extension that places channel-aware favorite custom emojis and reusable message presets next to YouTube Live Chat, enabling faster participation while keeping posting explicit and safe.

v1.0 should resist scope expansion into AI, cloud services, analytics, or unrelated streaming platforms.

The release criterion is not feature count. It is whether the extension is stable and convenient enough to remain enabled and be used routinely while watching YouTube Live.
